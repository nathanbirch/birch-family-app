# Themes

Ten coordinated themes, all defined in
[`src/config/themes.ts`](../src/config/themes.ts) and nowhere else. Ocean is
the default.

| Theme | Character |
|---|---|
| Ocean | Deep blue, bright blue, aqua, light coastal background *(default)* |
| Tropical | Teal, leaf green, sunshine accent, soft mint |
| Sunset | Coral, orange, rose, warm cream |
| Purple | Violet, indigo, lavender, very light purple |
| Forest | Evergreen, moss, sage, soft neutral |
| Berry | Raspberry, plum, soft pink, light rose |
| Sky | Cobalt, sky blue, pale blue, cloud grey |
| Sunshine | Amber, golden yellow, soft orange, warm ivory |
| Midnight | Dark navy, electric blue, muted purple — the only dark theme |
| Candy | Bright teal, pink, purple, soft pastel |

## How theming works

Components never reference a theme id or a hex value. They read semantic CSS
custom properties:

```css
--color-primary        --color-page-background   --scene-overlay
--color-primary-hover  --color-page-decoration   --scene-frame
--color-on-primary     --color-surface           --scene-floor
--color-secondary      --color-surface-muted
--color-accent         --color-text
--color-border         --color-text-muted
--color-focus-ring     --color-shadow
```

`themeCssVariables()` maps a theme onto those names, and `<ThemeStyles />`
renders one `[data-theme="…"]` block per theme into the document head. That is
the single place a token name meets a value — which is why there is no
`if (theme === "sunset")` anywhere in the codebase.

Switching themes sets one attribute on `<html>`. Everything else follows.

### The `scene` tokens

The two seating views are photographs, so a theme tints and frames them rather
than recolouring furniture:

| Token | Does |
|---|---|
| `overlay` | A wash laid over the photo |
| `frame` | The ring around the photo |
| `floor` | The surface behind it |

Midnight uses a dark `overlay` instead of a tint, which is how the photos stop
being glaringly bright in dark mode. It also sets `color-scheme: dark`, so
scrollbars and form controls match.

## Contrast

Every theme clears **4.5:1** for body text on its surfaces, muted text on its
surfaces, and text on its primary colour. The worst ratio across all ten is
**4.93:1** (Tropical). Three themes originally sat at 3.7–4.1 and had their
primary darkened to fix it.

## Persistence

Saved under `birch-family-seats:theme:v1`. To clear it:

```js
localStorage.removeItem("birch-family-seats:theme:v1");
```

This preference lives **only in the current browser on the current device**. It
does not sync — a theme picked on a phone will not appear on a laptop. That is
intentional: there is no server to sync with.

An unreadable or unrecognised stored value silently falls back to Ocean, and
the app still works when `localStorage` throws entirely (Safari private
browsing); the theme just won't survive a reload there.

## No flash of the wrong theme

A tiny inline script in the root layout runs before first paint. It reads the
stored theme, checks it against the known ids, and sets `data-theme` on
`<html>` — so the right colours are on screen from the very first frame. The
CSS for every theme is already in the document, so the script only has to set
one attribute. If storage is unavailable it fails silently and the default
stays.

React then adopts the same value through `useSyncExternalStore`, which is why
there is no hydration mismatch: the server renders Ocean, the client store
reads the real value, and React reconciles once.

The script is generated by `buildThemeInitScript()` from the same theme list as
everything else, so it can never drift out of sync. Tests execute it in a
sandbox to prove it applies valid themes, rejects invalid ones, and swallows a
storage failure.

## The picker

A single 44px button in the header opens a bottom sheet on phones and a popover
anchored under the trigger on wider screens.

It is rendered through a **portal into `document.body`**. That is not
incidental: the cards on the page run entrance animations, which give them
their own stacking contexts, and a panel left inside the header would be
painted underneath them no matter what z-index it carried.

Selection is never communicated by colour alone — the active theme carries a
checkmark and `aria-checked`. Escape closes the picker and returns focus to the
trigger.

## Changing themes

- **Change a colour** — edit that theme's `colors` or `scene` values.
- **Rename a theme** — change its `name`. Keep the `id`; that is what is stored.
- **Add or remove a theme** — add an entry to `THEMES` and its id to the
  `ThemeId` union. Note `tests/themes.test.tsx` asserts exactly ten themes;
  update that count if you change it.

Whatever you change, `npm test` verifies every theme still has every required
token, that ids are unique, and that Midnight is still the only dark one.
